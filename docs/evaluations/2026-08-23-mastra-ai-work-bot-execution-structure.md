## 평가 방식과 그 한계

**채점표 §8이 규정한 독립 다중 평가를 수행하지 않았다.** 개작자가 50개 항목을 직접 대조했으므로 작성자와 평가자가 같다. 따라서 아래 표는 통과 판정이 아니라 **자기 점검 결과**이고, 발행 전에 별도 평가가 필요하다.

기계로 잴 수 있는 항목은 도구로 확인했고, 판단이 필요한 항목은 근거 위치를 함께 적었다.

## 출처 재확인

개작 과정에서 본문의 사실 주장을 공식 문서로 다시 확인했다. **주장은 모두 문서와 일치했고, 문제는 그 출처가 글에 적혀 있지 않았다는 점이었다.**

확인한 항목: agent와 workflow의 구분 기준, `createTool`의 구성, `createStep`의 스키마, resourceId 변경 불가와 thread ID 재사용 시 오류, Observational Memory의 압축 방식, scorer의 0~1 점수, Node.js v22.13.0 이상·Hono 기반 서버·worker process 분리 권고.

## 발행 전 검증

- `pnpm format:check`: 통과
- `pnpm lint`: 통과
- `pnpm build`: 통과 (0 errors)
- 링크 접근성: 본문 URL 10건 전부 HTTP 200을 확인했다(2026-09-07, `curl -L`).
- 링크 접근성과 내용 대조는 다르다. **본문 내용까지 열어 원문 표현과 대조한 것은 `docs/memory/overview`와 `docs/deployment/overview` 두 건**이다. resourceId 변경 불가·thread ID 재사용 오류·Observational Memory 압축 방식·Node.js v22.13.0·Hono·worker process 분리가 그 두 문서에서 확인한 내용이다. 나머지 여섯 건은 공식 문서 검색 결과의 제목과 요약으로 주장 대응을 확인했으므로, 원문 표현까지 대조하려면 발행 전에 각각 열어야 한다.
